## Дефект метода: журнал трения слеп там, где болит

Прибор измерения работает через модель. Значит трение, случающееся при недоступной модели,
систематически не попадает в `log/friction.md`. Обе названные боли ровно из этого класса.

Отсюда: порог «три повтора» к этому классу неприменим, счётчик для него сломан по построению.
Оценивать такие дыры надо по факту возможности, а не по числу записей.

Чинится дёшево: функция быстрого захвата пишет в `inbox/`, туда же уходят и записи о трении,
сделанные без сети.

## Боль 1: бэкап и второй компьютер

Носить на флешке не выходит, забывает. Репозиторий 3.7 МБ, из них `.git` 2.6 МБ, `sources/`
960 КБ, `memory/` 184 КБ. Remote не заведён.

Вопрос не технический, а про содержимое: в памяти разговоры про чужой бизнес, оружейная тематика
и русификация прошивок прицелов.

- **Приватный remote на GitHub.** Проще всего, аккаунт есть, VPN настроен. Минус: содержимое на
  чужом сервере в юрисдикции, где эта тематика читается иначе.
- **Свой bare-репозиторий по SSH** на VPS или домашней машине через Tailscale. По ценностям
  [[qSerj|владельца]] лучший вариант, стоит денег или возни с доступом снаружи.
- **Syncthing** между домом и офисом. Без облака и аккаунта, но делает файлы-конфликты вместо
  merge и истории версий не даёт. Дополнение к git, не замена.
- **Файловое облако с папкой внутри не годится.** Живой `.git` через Яндекс.Диск и подобное
  ломается. Если облако всё же нужно, класть `git bundle create память.bundle --all`, один файл.

> [!important] Главное здесь не выбор хранилища
> Флешку он забывает, значит и `git push` будет забывать. Чинить надо привычку, а не носитель:
> хук `post-commit` с фоновым пушем плюс правило модели тянуть `pull` в начале сессии. Тогда
> забывать нечего.

## Боль 2: без сети система почти не работает

По стоимости, от бесплатного к сомнительному.

**Уже работает, нужна перепроверка.** `.obsidian` в хранилище теперь есть, а в записи журнала от
2026-08-31 его не было. Полнотекстовый поиск, граф, обратные ссылки и телефон, всё офлайн. На
двадцати одной странице это закрывает «достать из памяти» почти целиком. Ощущение «смотреть
неудобно» скорее всего относилось к сырым файлам без vault.

**Захват: функция в `.bashrc`.**

```bash
mem() { printf '\n%s\n' "$*" >> ~/Projects/MemorexClaude/inbox/$(date +%F)-быстрое.md; }
```

Тем же самым чинится слепота журнала: `mem "трение: ..."` уезжает в разбор при следующей сессии.

**Семантический поиск офлайн: питон, но не сейчас.** Локальный индекс эмбеддингов по `memory/`
плюс CLI, модель через LM Studio. Ровно тот питон снизу, который правила разрешают. Но на
двадцати одной странице поиск Obsidian не проигрывает вектору почти ничего. Триггер должен
остаться прежним и уже записанным в правилах: поиск промахнулся мимо страницы, которая точно есть.

**Слабая локальная модель для ответов: притормозить сильнее всего.** На русском мелкие модели
заметно хуже, и главное их свойство в том, что они уверенно искажают. Синтез по многим страницам,
ради которого модель и нужна, при двадцати одной странице не нужен. Цена ошибки высокая:
искажение будет выглядеть как ответ памяти.

**Правило-кандидат в правила:** офлайн пишем в `inbox/`, читаем из `memory/`, в `memory/` без
сильной модели не пишем ничего, кроме собственных правок владельца руками. Сохраняет и качество,
и смысл ворот `ingest`.
