# Что изменилось после пилота мобильной приёмки

Мобильную форму практически проверили на трёх вымышленных поставках. Проверка подтвердила, что бумажный лист можно убрать, но вечерний ручной перенос данных исчез не полностью: оператору всё ещё приходилось выгружать CSV и вручную загружать его в «Контур» [[warehouse-flows]].

После проверки изменились границы минимально полезного решения:

- интеграцию с «Контуром» стали считать обязательной частью полезного пилота, а не последующим улучшением;
- офлайн-режим стал обязательным, поскольку в зоне разгрузки пропала сеть;
- фотографии повреждений, наоборот, исключили из первого рабочего релиза, пока не определены сроки хранения и правила доступа;
- прежнюю оценку в два дня признали оценкой только макета экрана, а не готового решения [[warehouse-flows]] [[solution-boundaries]].

Проверка также выявила главное операционное узкое место — сопоставление кодов поставщика с внутренними SKU. Однозначное сохранённое соответствие нашлось для 63 из 80 строк; остальные позиции сотрудник выбирал вручную. Автоматически принимать первый результат поиска запретили [[warehouse-flows]].

**Синтез:** базовое архитектурное решение не изменилось: «Контур» остаётся ядром, но минимальная планка для мобильной надстройки выросла — она должна работать без сети и доводить данные до учётной системы. Фотографии при этом перестали быть обязательной частью первого релиза [[solution-boundaries]].

Остаётся неопределённость: в материалах не зафиксировано решение по авторизации, а сама проверка мобильной приёмки не названа формальным выбором единственного пилота; также неизвестно, что стало с параллельными улучшениями исходящего процесса [[warehouse-flows]] [[solution-boundaries]].
