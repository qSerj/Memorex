# memory-kit

Исходники скилла `memory-setup`. Он разворачивает внешнюю память на markdown в том каталоге, где
его запустили, и обновляет правила в уже развёрнутых хранилищах, не трогая накопленное.

Текущая версия в файле `VERSION`.

## Что разворачивается

```text
CLAUDE.md            правила, грузятся каждый ход. Во frontmatter версия комплекта
.claude/skills/      remember, ingest, review
sources/             оригиналы как пришли, только добавляются
memory/              страницы знаний, плоско, связи через [[wikilinks]]
actions/             open.md и done.md
inbox/               входящее и пины
log/friction.md      журнал трения
documents/           только если в хранилище производятся договоры и регламенты
```

Плюс git с первым коммитом.

## Установка скилла

```bash
./build.sh
```

Получается `memory-setup.zip`. Добавить его как скилл в интерфейсе Claude Code. Повторное
добавление обновит скилл до собранной версии.

Хранилища при этом **не меняются**. Каждое несёт собственные копии правил и продолжает работать
на своей версии, пока в нём явно не запустить обновление. Удаление скилла тоже ничего не ломает:
теряется только возможность ставить новые хранилища и обновлять старые.

## Завести хранилище

Создать пустой каталог, открыть в нём Claude Code, сказать «заведи память». Три вопроса, и каркас
собран.

Если каталог оказался внутри существующего репозитория, скилл остановится и спросит, как жить с
историей: свой репозиторий внутри проекта или общие коммиты только по путям памяти.

## Обновить существующее хранилище

Зайти в него и сказать «обнови правила памяти». Скилл сравнит версию хранилища с версией скилла и:

- версия хранилища меньше, предложит обновление и прогонит миграции по ступеням;
- версии равны, предложит только переустановку правил на случай порчи файлов;
- версия хранилища больше, откажется работать. Старые правила на новые данные не накатываются.

Память, источники, действия и журнал обновление не трогает. Их меняют только миграции, и только
по правилам из `migrations/README.md`.

## Как менять правила

1. Править `references/`.
2. Если правка требует чего-то от уже накопленных страниц, написать миграцию в `migrations/`.
   Формат и запреты описаны в `migrations/README.md`.
3. Поднять `VERSION` по semver. Ступень миграции обязана совпадать с новой версией.
4. `./build.sh`, добавить архив как скилл заново.
5. Пройти по хранилищам и обновить те, которые нужны. Не обязательно все и не обязательно сразу.

Правка, сделанная внутри хранилища и не перенесённая сюда, потеряется при следующем обновлении
этого хранилища. Комплект это источник правил, хранилище это их потребитель.

## Откуда правила

Выращены в `~/Projects/MemorexClaude` на реальном использовании: расшифровки разговоров, статьи,
заметки. Каждое правило либо закрывает записанную в журнал боль, либо взято из чужого опыта
эксплуатации такого же хранилища.
