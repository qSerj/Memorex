# 1.1.0 → 1.2.0

## Что изменилось в правилах

Абзац теперь пишется одной строкой: перенос ставится там, где абзац кончился, а не по ширине
текста. Obsidian показывает одиночный перевод строки как настоящий разрыв, поэтому завёрнутый по
ширине абзац разваливается на рваные куски и готовая страница читается как черновик.

Правило написано ради уже написанных страниц, а не только будущих, поэтому и нужна эта ступень.

## Что сделать с существующими данными

Обрабатывать файлы `.md` в `memory/`, `actions/`, `inbox/` и `documents/`, если она есть. Каждый
файл по отдельности, а не оптом.

**Шаг 1. Разметить файл на блоки.** Читать сверху вниз и отмечать границы: frontmatter между
`---`, блоки кода в ``` и ~~~ вместе с содержимым, таблицы, списки вместе с их вложенными
строками, цитаты `>`, заголовки `#`, строки с отступом в четыре пробела или табуляцию, строки
определений ссылок вида `[метка]: url`. Всё остальное — обычные абзацы.

**Шаг 2. Схлопнуть только обычные абзацы.** Идущие подряд непустые строки одного абзаца
соединить в одну через пробел. Пустая строка между абзацами остаётся пустой строкой. Число
абзацев в файле не меняется: меняется только то, чем они разорваны внутри.

**Шаг 3. Оставить как есть всё остальное.** Отмеченные на шаге 1 блоки переносятся в результат
байт в байт.

**Шаг 4. Проверить, что ни одного слова не потеряно.** Для каждого файла до и после:

```bash
tr -s '[:space:]' '\n' < "$f" | sort | md5sum
```

Суммы обязаны совпасть. Схлопывание меняет только пробельные символы, поэтому несовпадение
означает ошибку обработки, а не улучшение. Файл с несовпадением вернуть в прежний вид и назвать
в отчёте.

**Шаг 5. Пропускать сомнительное.** Страницу не трогать и назвать её в отчёте, если в ней
встретилось хоть одно из:

- строка, кончающаяся двумя пробелами или обратной косой чертой: это намеренный жёсткий перенос,
  и схлопывать его нельзя;
- пункт списка, продолженный следующей строкой без отступа, — непонятно, продолжение это или
  новый пункт;
- вложенные друг в друга блоки, где граница читается неоднозначно: таблица внутри цитаты,
  блок кода внутри пункта списка;
- смешанные отступы из пробелов и табуляций в одном блоке.

Лучше пропустить десять страниц, чем незаметно испортить одну.

**Шаг 6.** Коммит: `миграция 1.1.0 → 1.2.0: абзац одной строкой, N файлов`.

## Чего не делать

- Не трогать `sources/`. Оригиналы неприкосновенны.
- Не трогать `log/friction.md`: его формат задан внутри самого файла.
- Не трогать `CLAUDE.md` и файлы скиллов. Правила читают в редакторе, там перенос по ширине уместен.
- Не переписывать текст. Миграция меняет только пробельные символы. Ни одного слова не добавить,
  не убрать и не переставить.
- Не чинить заодно теги, заголовки, ссылки и опечатки. Это другая работа.
- Не удалять и не создавать страницы.

## Как проверить, что вышло

Показать владельцу:

- сколько файлов затронуто и сколько пропущено, с именами пропущенных и причиной по каждому;
- результат проверки из шага 4 одной строкой: все суммы совпали или нет;
- `git diff --stat` и одну страницу до и после целиком, чтобы было видно, что изменились
  переносы, а не текст.

Если после миграции `git diff` показывает изменения где-то кроме переносов строк, это ошибка.
