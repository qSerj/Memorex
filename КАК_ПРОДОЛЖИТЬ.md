# Как продолжить разработку Memorex Wiki-first Web UI

## Точка передачи

Работа выполнена в ветке `wiki-first`. От исходного коммита `9794fa9` создана отдельная ветка
`experiment/agent-host`; в неё не добавлялись OpenCode/Hermes-конфигурация, skills или MCP.
Локальный приватный workspace `my-knowledge/` добавлен в `.gitignore`, не читался и не изменялся.

На момент передачи проходят:

```bash
UV_CACHE_DIR=/tmp/memorex-uv uv run ruff check .
UV_CACHE_DIR=/tmp/memorex-uv uv run ruff format --check .
UV_CACHE_DIR=/tmp/memorex-uv uv run pytest -q
# 40 passed
```

## Что реализовано

- `memorex app [PATH]`: отдельное Wiki-first приложение на loopback с выбором/созданием workspace
  и сохранением последнего пути; старый `memorex serve` не переделан.
- Локальные Jinja/CSS/JS без Node и CDN; экраны Wiki, Inbox, Review, Chat, History и фоновой задачи.
- Upload только UTF-8 `.txt`/`.md` до 10 MiB, безопасные имена/пути, HTML в Markdown экранируется.
- Review без ручных job ID: Apply/Reject/Revise над текущим proposal, rendered result, before/after,
  скрытый diff и отчёт о числе переданных модели страниц.
- SQLite FTS5 активной Wiki с links/backlinks. Ingest выбирает до 8 найденных + 4 связанных страниц,
  query — до 6 + 4; отсутствие query-кандидатов не вызывает full-Wiki fallback.
- Runner получает только выбранные страницы, процитированные ими sources и новые sources.
  Непереданные страницы сохраняются детерминированным merge поверх полного базового snapshot.
- `proposal-actions.json` валидируется Pydantic; delete/rename возможны только через явный manifest.
  Для старых fake runners без manifest безопасно выводятся только upsert-действия для созданных файлов.
- Claude/Codex запускаются через потоковый `Popen`; JSON/JSONL сводится к безопасным стадиям без
  model reasoning. События сохраняются в SQLite и передаются через SSE. Есть fallback и Stop.
- Mutation executor однопоточный на workspace; query executor отдельный, поэтому Chat может читать
  активный snapshot параллельно ingest/revise.
- Chat sessions/messages сохраняются. Модели передаются последние 10 реплик, не более 16 000
  символов, явно как context, не evidence. Ответ привязан к snapshot.
- После Apply/Rollback/Refresh атомарно перестраивается стабильный read-only `WORKSPACE/vault/` с
  `wiki/` и `sources/`; внешние изменения vault заменяются.
- Добавлены offline regression tests для Web setup/upload/last workspace/HTML escaping и проверки,
  что runner физически не видит нерелевантную страницу, а merge и vault её сохраняют.

## Осознанные компромиссы и следующие шаги

1. Добавить более подробные ASGI-тесты фонового lifecycle: fallback, Stop реального долгого fake
   runner, persisted SSE, Retry и одновременный ask во время ingest. Сейчас механизмы есть, но полный
   набор сценариев из исходного плана тестами не покрыт.
2. При восстановлении abandoned `running` job хранится статус `failed` с причиной, содержащей
   `interrupted`; Web показывает его как `interrupted` и даёт Retry. Это оставлено для совместимости
   с существующим тестом. Если совместимость больше не нужна, в `recover_interrupted_jobs()` можно
   хранить отдельный статус `interrupted` и обновить тест.
3. Усилить lifecycle revise: сейчас job временно получает `running` и возвращается в `proposed`,
   если runner падает. Стоит добавить отдельный persisted task status, чтобы job и task не делили
   семантику состояния.
4. Добавить тесты явных delete/rename manifest, traversal в manifest/source route, oversize/non-UTF8
   upload, broken JSON manifest и сохранения chat context ровно в лимитах.
5. Проверить команды Claude Code на установленной версии: используется `--output-format stream-json
   --verbose`. Реальный endpoint/agent smoke запускать только вручную на несекретном корпусе или в
   ignored приватном workspace.
6. UI остаётся первым функциональным milestone: улучшить мобильную вёрстку before/after, сделать
   drag-and-drop отправку без выбора файла и добавить более информативный список chat sessions.
7. `WikiStorage.initialize()` сейчас гарантирует актуальность FTS/vault и поэтому перестраивает их
   часто. После профилирования можно разделить schema initialization и явный refresh после
   Apply/Rollback, сохранив проверку целостности.

## Быстрый ручной smoke

```bash
uv run memorex app /tmp/memorex-smoke
```

В setup создать workspace, загрузить `.txt`, запустить ingest и наблюдать стадии. Для реального
ingest должен быть установлен и авторизован Claude Code или Codex CLI. Proposal не активируется до
нажатия Apply. После Apply проверить `vault/`, Wiki backlinks, source locator, Chat и Rollback.

## Границы

- Первый milestone принимает только UTF-8 TXT/Markdown.
- Приложение локальное, однопользовательское, без авторизации и не публикуется наружу.
- OpenCode/Hermes-hosted эксперимент продолжать только в `experiment/agent-host`, не в `wiki-first`.
