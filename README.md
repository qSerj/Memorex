# Memorex

**Memorex — локальная персональная внешняя память с AI.**

Это обычный заметочник, в который можно складывать мысли, документы, изображения, ссылки и другие
материалы, а AI помогает разбирать накопившееся, связывать новое с уже известным и обсуждать
сохранённое.

Главный принцип проекта:

> Пользователь не обязан быть дисциплинированным.
> Система должна помогать помнить и организовывать вместо него.

Memorex не требует AI для обычной работы. Заметки можно создавать, редактировать, искать,
раскладывать по блокнотам и снабжать вложениями полностью локально. Если Claude или Codex
недоступны, память остаётся доступной.

---

## Зачем это нужно

Обычный сценарий выглядит примерно так.

Нашёл фильм, который хочется посмотреть:

> Посмотреть Good Luck Have Fun Don't Die

Сохранил номер автомобильной детали:

> Кажется, этот фильтр подходит к моей машине. Проверить при следующем ТО.

Получил документ — положил его в память.

Нашёл интересную статью — сохранил ссылку с коротким комментарием, зачем она нужна.

Через месяц можно найти нужную заметку обычным поиском или открыть несколько связанных заметок и
обсудить их с AI.

Memorex задуман как место, куда можно спокойно складывать собственную жизнь, не пытаясь заранее
идеально определить папку, тип документа, теги и структуру.

---

## Два способа что-нибудь сохранить

### Обычная заметка

Если вы уже знаете, что хотите записать, проще всего создать обычную заметку.

Например:

- список фильмов;
- показания счётчиков;
- номер детали;
- идея;
- памятка;
- список вопросов;
- медицинская информация;
- рабочая заметка.

Заметка принадлежит пользователю.

Её можно открыть, переписать, сократить, превратить в таблицу, перенести в другой блокнот или
добавить вложения. AI для этого не нужен.

### Добавить сырой материал

Иногда в руках не готовая заметка, а кусок информации:

- несколько файлов;
- изображение;
- текстовый комментарий;
- одна или несколько ссылок;
- материалы, которые относятся к одной теме.

Экран **«Добавить»** позволяет сохранить всё это одним действием.

Сначала материал гарантированно сохраняется локально. После этого AI может в фоне разобрать его и
предложить изменения в существующих заметках или новые заметки.

Пользователь может принять предложение, отклонить его или исправить результат самостоятельно.

Внутри Memorex такое добавление называется `Packet`, но пользователю знать этот термин для обычной
работы не требуется.

## Что уже умеет Memorex

### Заметки

- создание обычных Markdown-заметок;
- ручное редактирование;
- предпросмотр;
- блокноты;
- «Входящие»;
- изображения и другие вложения;
- история версий;
- Wiki-ссылки между заметками.

### Поиск

Локальный полнотекстовый поиск работает без AI и сети.

Он предназначен для простых запросов вроде:

> Где моя заметка про фильтр?

> Что я сохранял про GraphRAG?

AI для этого не вызывается.

### AI-разбор материалов

AI может разобрать сохранённый материал и предложить:

- новую заметку;
- дополнение существующей заметки;
- объединение информации из нескольких источников;
- связи с уже сохранённым.

AI не изменяет пользовательскую память молча. Изменения модели сначала попадают **на проверку**.
Ручные изменения пользователя применяются сразу.

### Обсуждения с AI

Одну или несколько заметок можно выбрать и открыть отдельное обсуждение.

Например:

> Сравни эти варианты.

> Что из этих заметок следует?

> Какие вопросы я здесь упустил?

> Помоги принять решение.

Перед обращением к модели пользователь видит, какие заметки войдут в контекст.

Разговор сам по себе не переписывает память. Полезный ответ можно сохранить как новую обычную
заметку.

### Надёжное сохранение

AI может работать долго, сеть может оборваться, а внешний runner может завершиться ошибкой.
Поэтому сохранение материала и AI-анализ разделены.

Сначала данные сохраняются локально, после чего обработка выполняется фоновой очередью. Очередь:

- переживает перезапуск приложения;
- не должна терять сохранённый материал;
- ограниченно повторяет технические ошибки;
- позволяет следующим материалам обрабатываться, даже если предыдущий результат ждёт проверки;
- показывает пользователю состояние обработки.

### Резервная копия и перенос

Workspace можно целиком скачать как `.memorex.zip` и восстановить на другой машине. В архив входят
заметки, вложения, исходные материалы, история, обсуждения и служебное состояние Memorex.

Перед восстановлением поверх существующего workspace старая версия автоматически сохраняется
отдельной страховочной копией.

Также можно скачать обычный читаемый ZIP. В нём находятся Markdown-заметки, исходные материалы и
вложения без SQLite, очередей и служебных журналов. Такой архив можно открыть без Memorex.

## Как запустить

Требуются:

- Python 3.13;
- `uv`.

Для AI-функций дополнительно нужен авторизованный Claude Code или Codex CLI.

```bash
uv sync --locked --all-groups
```

После этого можно сразу запустить приложение:

```bash
uv run memorex app
```

При первом запуске Memorex предложит создать новый workspace или открыть существующий.

Можно также указать путь явно:

```bash
uv run memorex app ./my-knowledge
```

Приложение работает локально на:

```text
http://127.0.0.1:8766
```

Предварительно выполнять `workspace init` для обычной работы через Web-интерфейс не требуется.

## Основной интерфейс

Сейчас в приложении есть несколько основных разделов.

### Заметки

Обычная работа с памятью:

- список заметок;
- блокноты;
- локальный поиск;
- создание и редактирование;
- вложения.

### Добавить

Быстро сохранить необработанный материал:

- комментарий или мысль;
- несколько TXT/Markdown-файлов;
- изображения;
- ссылки.

Сохранение происходит сразу. AI-анализ выполняется отдельно.

### Обсуждения

Постоянные разговоры с AI по явно выбранным заметкам.

### На проверку

Предложения, которые подготовил AI. Пользователь решает, принимать ли их в память.

### История

Предыдущие версии заметок и изменения памяти.

### Перенос

Полная резервная копия, читаемый экспорт и восстановление workspace.

## Какие файлы поддерживаются

Сейчас напрямую поддерживаются:

- `.txt`;
- `.md`;
- `.png`;
- `.jpg`;
- `.jpeg`;
- `.webp`.

Размер одного загружаемого файла — до 10 MiB.

Изображение можно:

- передать AI для анализа;
- сохранить без анализа;
- снабдить отдельной инструкцией вроде «распознай таблицу» или «интересует только название
  устройства».

Отдельный OCR-конвейер не используется: модель работает непосредственно с изображением.

## Ссылки

URL уже можно сохранять вместе с другими материалами.

**Текущая версия пока не скачивает содержимое страницы автоматически.**

То есть ссылка сохраняется в памяти, но импорт статьи или другого Web-содержимого ещё находится в
разработке.

## Как Memorex использует AI

AI здесь не является владельцем базы.

Правило простое:

> **Пользовательская правка — это решение.
> AI-правка — это предложение.**

Если пользователь редактирует заметку вручную, изменение сохраняется сразу. Если модель хочет
создать или изменить заметку, результат сначала показывается пользователю.

Существующая заметка также задаёт желаемую форму информации. Если человек уже сделал страницу
списком, таблицей или короткой памяткой, AI должен по возможности продолжать эту структуру, а не
перестраивать её без необходимости.

Для небольших добавлений Memorex использует быстрый профиль модели, для обычного анализа и
обсуждений — стандартный. При техническом сбое возможна одна попытка через резервный runner. На
одну пользовательскую операцию приходится не более двух вызовов модели.

---

## Локальность и приватность

Заметки, вложения, история и служебные данные Memorex хранятся локально в workspace.

Обычные функции заметочника и поиска не требуют сети.

При использовании AI выбранный материал передаётся настроенному внешнему runner'у, например Claude
Code или Codex CLI. Не следует отправлять через внешние модели данные, которые вы не готовы
передавать соответствующему провайдеру.

## Куда развивается проект

У Memorex сейчас три последовательных уровня ценности.

### 1. Я ничего не теряю

Информация быстро и надёжно сохраняется.

### 2. Мне не нужно идеально всё организовывать

Можно вести обычные заметки, а AI помогает разбирать сложный и неопрятный поток материалов.

### 3. Система возвращает нужное вовремя

В будущем Memorex должен уметь замечать намерения вроде:

- сделать;
- сделать к сроку;
- дождаться ответа;
- вернуться к этому позже;

и помогать возвращать их вниманию пользователя.

Этот слой пока развивается постепенно и не должен превращать Memorex в систему, требующую
обязательного GTD-ритуала. Сначала Memorex должен оставаться хорошей и надёжной внешней памятью.

---

## Важный принцип разработки

Memorex развивается прежде всего через реальное использование.

Новая подсистема должна появляться не потому, что она архитектурно красива, а потому, что
существующая система обнаружила конкретное ограничение.

Принцип проекта:

> Добавлять машинерию там, где более простое решение уже показало реальный отказ.

Поэтому внутри проекта могут существовать экспериментальные или старые реализации, которые не
являются частью текущей пользовательской модели.

## Для разработчиков

Текущая продуктовая модель подробнее описана в
[`06_EXTERNAL_MEMORY_DIRECTION.md`](06_EXTERNAL_MEMORY_DIRECTION.md).

Текущее состояние реализации находится в
[`05_IMPLEMENTATION_STATUS.md`](05_IMPLEMENTATION_STATUS.md), а внутреннее устройство — в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

Старый provenance-oriented knowledge compiler сохранён в репозитории как исследовательский
прототип, но больше не определяет основной пользовательский путь Memorex.

Разработка:

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Тесты работают офлайн и используют fake runners/providers.

## Коротко

Memorex — это не система, в которой AI пытается построить идеальную Wiki вместо пользователя.

Это **локальная записная книжка и внешняя память, которой владеет человек**, а AI помогает:

- разбирать сырой материал;
- связывать информацию;
- находить смысл;
- обсуждать накопленное;
- и со временем — помнить о том, что требует внимания.

Если AI недоступен, записная книжка остаётся записной книжкой.
