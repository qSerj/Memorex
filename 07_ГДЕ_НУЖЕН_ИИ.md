# Где нужен ИИ, где хватит дешёвого, где не нужен вовсе

Updated: 2026-09-03

Документ описывает **markdown-воплощение** Memorex: правила в `CLAUDE.md`, скиллы и пять папок,
развёрнутые комплектом `memory-setup`. Рабочий экземпляр живёт в `~/Projects/MemorexClaude` и
используется ежедневно с 26.08.2026. Документы `00`–`06` описывают другую линию, python-приложение,
и к этому тексту отношения не имеют.

Вопрос практический: подписка на сильную модель стоит денег и может стать недоступной не по воле
владельца. Поэтому важно знать по каждой операции, что именно сломается.

## Три уровня

| Операция | Уровень | Чем закрывается |
|---|---|---|
| Сохранить оригинал в `sources/` | без модели | перемещение файла |
| Быстрый захват мысли | без модели | строка в `inbox/` |
| Создать страницу руками | без модели | любой редактор, правилами это **решение**, а не нарушение |
| Чтение и навигация | без модели | Obsidian: обратные ссылки, несвязанные упоминания, граф |
| Поиск по словам | без модели | `grep`, поиск Obsidian |
| История, диффы, откат, перенос на другую машину | без модели | `git` |
| Поиск по смыслу | дешёвая, локальная | эмбеддинги, генерация не нужна |
| Подсказка тегов | дешёвая | короткий структурный вывод |
| Маршрутизация: это `remember` или `ingest` | дешёвая | выбор из двух |
| Пересказ одного короткого источника | дешёвая | один вход, короткий выход |
| Разбор большого грязного входа на темы | **сильная** | много источников, решение что выбросить |
| Противоречия между источниками и между страницами | **сильная** | сопоставление далеко разнесённого |
| Куда встроить и что переписать | **сильная** | правка существующего без порчи |
| Синтез по многим страницам, обсуждение | **сильная** | то, ради чего память и держат |
| «Что стоит выяснить дальше» | **сильная** | нужно видеть дырки, а не текст |

Первичное сохранение и чтение не требуют модели вообще. Это не пожелание на будущее, а текущее
положение дел.

## Почему дешёвая модель вообще возможна

Ворота `ingest` снижают требование к качеству модели.

Без ворот нужна модель, которой доверяешь без надзора: её вывод идёт прямо в память. С воротами
достаточно модели, дающей полезный черновик, потому что карту тем всё равно читает и правит
человек, и его правки главнее предложенного.

Механизм, позволяющий удешевить ИИ, уже стоит в архитектуре. Поставлен он был по другой причине,
ради контроля над памятью, а удешевление оказалось побочным следствием.

Граница трезвая. Дешёвая модель годится там, где выполняются **оба** условия сразу: человек и так
собирался проверять, и вывод короткий и структурный. На девяти черновиках слабая модель создаст
больше работы, чем сэкономит. Для синтеза не годится вовсе: там проверять нечего, там либо есть
мысль, либо её нет.

> [!warning] Столбец «дешёвая» пока гипотеза
> На локальной модели не прогонялось ничего. Ни смысловой поиск, ни разбор, ни маршрутизация.
> Пока это рассуждение о том, где это уместно, а не измерение того, где это работает.

## Как работать совсем без модели

Три вещи, которые надо уметь без сети и без подписки.

**Сохранить мысль.** Функция в `.bashrc`, без редактора и без сети:

```bash
mem() { printf '\n%s\n' "$*" >> ~/Projects/MemorexClaude/inbox/$(date +%F)-быстрое.md; }
```

`mem "мысль"`, и она в очереди на разбор. Тем же способом пишется трение, случившееся без модели:
иначе оно не попадёт в журнал никогда, потому что журнал ведётся через сессию.

**Сохранить материал.** Положить файл в `inbox/`. Разбирать его будут позже, оригинал не пропадёт.

**Достать накопленное.** Obsidian, открытый на корне хранилища. Поиск по всему тексту, переход по
викиссылкам, панель обратных ссылок и, что важнее всего, **несвязанные упоминания**: они показывают
страницы, где тема названа текстом, но ссылки нет. Это ровно один из пунктов проверки памяти,
только мгновенно, офлайн и бесплатно.

**Править память руками разрешено.** Правка владельца это решение и применяется как есть. Запрещено
обратное: чтобы модель писала в память молча.

## Что теряется без сильной модели

Честный список, без утешений:

- пакетный разбор грязного входа: пачка расшифровок останется пачкой расшифровок;
- поиск противоречий между страницами, накопленных со временем;
- синтез по многим страницам и обсуждение, то есть главная ценность;
- подсказка о том, чего в памяти не хватает.

Библиотека при этом не теряется вообще: markdown на своём диске, в git, читаемый чем угодно.
Подписка покупает работника, а не доступ. Разница видна в момент отказа: теряется писатель, а не
чтение.

Зависимость растёт вместе с хранилищем. На двадцати страницах Obsidian закрывает чтение целиком.
На пятистах синтез станет тем, ради чего память и держат, и его отсутствие будет заметно.

## Заменяемость сильной модели

Правила лежат в текстовом файле и не привязаны к поставщику. В хранилище положен `AGENTS.md`
(02.09.2026) для агентов, читающих его вместо `CLAUDE.md`. Это не симлинк: Codex и OpenCode не
подхватывают скиллы, поэтому файл сделан маршрутизатором, который указывает, какой `SKILL.md`
читать под какую операцию.

Проверка на Codex ещё не проведена. До неё утверждение «дорогая часть заменяема» остаётся
рассуждением.

## Что из этого следует для развития

Настоящий риск не цена, а доступ: оплата и доступность сервиса могут отвалиться не по воле
владельца. Значит приоритет у того, что удерживает систему живой при пропаже модели.

По убыванию пользы:

1. Прогнать хранилище под Codex и записать, что сломалось. Дёшево, закрывает вопрос заменяемости.
2. Смысловой поиск на локальных эмбеддингах. Единственная операция, где локальная модель почти
   наверняка достаточна, потому что генерация не нужна. Заводить не раньше, чем поиск по словам
   начнёт промахиваться: порог уже записан в правилах.
3. Всё остальное на дешёвой модели проверять только после того, как первые два пункта дадут факты.
