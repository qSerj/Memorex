## Overview

Проверка гипотезы: то, что делает [[Memorex]], закрывается связкой `CLAUDE.md` плюс скиллы плюс
markdown-файлы, без питона, веб-интерфейса и очереди задач. Интеллект живёт в модели, питон
появляется снизу как инструмент, а не сверху как диспетчер над моделью.

Повод: работа над [[Memorex]] съезжала в сторону написания ещё одного GUI поверх Claude Code. Две
конкретные точки. Страница добавления знания получалась уродливой, и непонятно, как сделать её
хорошо. Диалог по статьям, выбранным галочками, оказался ручной эмуляцией того, что агентная среда
делает сама и лучше, потому что выбор контекста у неё динамический.

> [!important] Правило эксперимента
> Неделю пользоваться и не писать код. Решение о любом внешнем куске принимается только по фактам
> из журнала трения, а не по желанию что-нибудь построить.

## Current Status

Каркас развёрнут в `~/Projects/MemorexClaude` (2026-08-26, пустая папка до этого): корневой
`CLAUDE.md`, три скилла, пять папок `sources / memory / actions / inbox / log`.

Первый прогон в тот же день дал две правки правил, обе из реального использования, а не из
рассуждения. Захват одной мысли отработал чисто (страница про HAPP). Дальше нашлись две дыры.

Правило «сирот не создавать» не выполнимо в молодом хранилище: связывать не с чем, а натянутая
связь хуже одиночной страницы. Ослаблено, проверка на сирот уехала в `review`.

Скилл `remember` не тянет большой грязный вход. Одиннадцать расшифровок разговоров дают не одну
страницу, и человек должен посмотреть на выделенные темы до записи в память. Добавлен третий скилл
`ingest`: оригиналы в `sources/` сразу, затем карта тем в `inbox/_разбор-ДАТА.md` для правки руками,
и только по явному «применяй» темы уходят в `memory/`. В карте обязателен раздел «Не взял», чтобы
было видно выброшенное, плюс противоречия и действия.

Идея ворот взята из демонстрационного `CLAUDE.md` в духе [[LLM-Wiki]] (шаг «обсудить с человеком до
записи»). Оттуда же взят разбор противоречий между источниками. Вместо глобального оглавления
страница-хаб по конкретному сюжету, когда из разбора вышло больше четырёх связанных страниц.

Разбор первоисточника паттерна ([[LLM Wiki (Карпатый)]], gist от 2026) дал ещё три правки, см.
[[Что взято из LLM Wiki]]. Главная: хороший ответ в разговоре это материал для памяти наравне с
источником, и предлагать его сохранение теперь обязанность, а не любезность. Раньше вывод попадал в
память, только если [[qSerj]] сам вспомнит сказать «запомни».

Сознательное отличие от готовых персональных ОС на Obsidian вроде этого vault: там таблица
маршрутизации «каждый тип информации имеет свой дом», здесь её нет. Такая онтология придумана
заранее и под чужую задачу. Владелец бросает материал, решение о размещении принимает агент.

## Open Questions

Два ожидаемых остатка, которые агентная среда закрыть не может: надёжный захват извне при закрытой
сессии (share с телефона, watched folder, кнопка в браузере) и напоминания, срабатывающие
независимо от открытого чата. Если они подтвердятся журналом, настоящий [[Memorex]] окажется не
приложением, а двумя маленькими сервисами под агентом. Гипотеза может и не подтвердиться, это
нормальный исход.
